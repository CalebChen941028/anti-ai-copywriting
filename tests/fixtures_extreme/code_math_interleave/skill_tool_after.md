# DPDK 零拷贝网络改造实测通报

## 一、实测结论

100 Gbps 以太网口压测下，单核心收包吞吐 14.88 Mpps，单包端到端处理时延由 850 ns 降至 120 ns；单包处理时间复杂度由 $O(N)$ 降为 $O(1)$，内存拷贝开销减少 64 GB 带宽。

## 二、改造机制

三条机制作用于同一条收包路径。

**大页内存。** 收发包内存池与描述符环由 2MB HugePages 承载，页表遍历频次下降，地址转换不再随报文速率升高而成为瓶颈。

**用户态 PMD 轮询。** 收包绕开中断与内核协议栈，报文落入用户态 mbuf 后由应用直接读取，中断上下文切换与软中断开销随之消除。

**零拷贝。** 内核缓冲区到用户态缓冲区的那道复制被取消，报文数据全程原地驻留，原本用于搬运的内存带宽得到释放。

## 三、收包路径

```c
// DPDK burst polling loop
uint16_t nb_rx = rte_eth_rx_burst(port_id, 0, pkts_burst, 32);
```

该调用取回一批已就绪报文，返回值为实际收到的个数，应用随即批量处理。轮询与批处理叠加，逐包中断与逐包复制两笔开销同时消失。

## 四、性能变化的来源

时延下降来自三处叠加：中断路径移除后，报文到达与处理之间不再有调度等待；零拷贝免去了数据搬运；大页压低了地址转换的固定成本。

复杂度由线性转为常数，指处理路径上不存在随规模增长的遍历，单包工作量不随队列长度或报文数量变化。

## 五、提交前需补齐的口径

1. **带宽节省项**未标单位与统计区间，需说明是瞬时带宽（GB/s）还是压测区间内的累计搬运量，两者量纲不同。
2. **$O(N)$ 中 N 的所指**未定义，需指明是突发队列长度、活跃流数量还是其他维度，复杂度结论才能对齐。
3. **测试条件**缺项：包长、硬件平台、核绑定方式、网卡型号、队列配置、压测工具与压测时长。上述任一项变动都会改变吞吐与时延的复现结果。
4. **改造前吞吐**无基线数值，现结论缺少参照。
