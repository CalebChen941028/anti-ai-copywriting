# DPDK 零拷贝网络改造实测通报

## 一、改造路径

数据面收包由用户态 PMD 轮询驱动承担，不再经过内核协议栈。收发包内存在大页（HugePages，2MB）上分配。内核缓冲区与用户态缓冲区之间的逐包拷贝在改造后取消，这是“零拷贝”所指的具体动作。

## 二、实测数据

测试在 100Gbps 以太网口上进行，单核运行。三项结果分别落在吞吐、时延与拷贝路径上：

- 单核吞吐 14.88 Mpps。
- 单包端到端处理时延由 850 ns 降至 120 ns。
- 内存拷贝路径的时间复杂度由 $O(N)$ 降为 $O(1)$，拷贝开销节约 64GB 带宽。

## 三、收包循环

```c
// DPDK burst polling loop
uint16_t nb_rx = rte_eth_rx_burst(port_id, 0, pkts_burst, 32);
```

单次轮询的批量上限由 `nb_pkts` 参数给定，实际收到的包数取返回值 `nb_rx`，调用方按 `nb_rx` 遍历 `pkts_burst` 的前若干项。轮询模式下收包不依赖中断。

## 四、口径边界

吞吐项未标注平均帧长与线速占比，且缺改造前基线，横向比较缺少共同分母。时延项未记录基线所对应的软件栈、120 ns 的采样点位置以及测量方法。拷贝开销一项原文记为 GB，带宽量纲应为 GB/s，统计区间同样空缺。$O(N) \to O(1)$ 中的 $N$ 限定在内存拷贝环节，不外推至整条处理链。测试主机的软硬件版本与核绑定策略未列出，结果可复现性依赖这些前置条件。

## 五、结论

改造后收包路径在单核下达到通报吞吐值，单包时延与拷贝复杂度两项构成完整的前后对比。吞吐一项只有改造后的绝对值，暂不支撑“提升”这一表述；跨平台结论待第四节所列口径补齐后给出。
