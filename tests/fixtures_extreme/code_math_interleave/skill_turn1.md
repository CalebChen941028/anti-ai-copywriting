# DPDK 零拷贝网络改造：实测结果通报

## 一、改造内容

收包路径改用用户态 PMD 轮询驱动，不再经过内核协议栈；内存由 2MB 大页（HugePages）承载，以降低 TLB 未命中频次。数据面不再执行内核缓冲区到用户态缓冲区的逐包拷贝。

## 二、实测结果

测试口为 100Gbps 以太网口，单核运行。

| 指标 | 改造前 | 改造后 |
| --- | --- | --- |
| 单核吞吐 | 未给出基线 | 14.88 Mpps |
| 单包端到端处理时延 | 850 ns | 120 ns |
| 内存拷贝时间复杂度 | $O(N)$ | $O(1)$ |
| 内存拷贝带宽开销 | 未给出基线 | 节约 64GB |

三项结果分别取自吞吐、时延与拷贝路径，测量口径见第四节。

## 三、收包循环

```c
// DPDK burst polling loop
uint16_t nb_rx = rte_eth_rx_burst(port_id, 0, pkts_burst, 32);
```

`nb_pkts` 取 32，即单次轮询最多取 32 个包，实际收包数由返回值 `nb_rx` 给出。轮询模式下收包不依赖中断。

## 四、数据口径与待确认项

1. **吞吐**：14.88 Mpps 未标注平均帧长。按 100Gbps 折算，该数值对应约 840 字节/帧（含前导码与帧间隙）；需补帧长分布或线速占比，否则无法与其他平台横向比较。
2. **时延**：850 ns 基线所对应的软件栈（内核协议栈或其他）与测量方法（硬件时间戳、回环、RFC 2544）未注明；120 ns 的采样点位置（网卡出口至应用层，或至业务处理返回）需明确。
3. **内存带宽**：原文记为“节约 64GB 带宽”，量纲不一致——GB 是容量单位，带宽应为 GB/s。需确认该值是累计传输量还是速率，并给出统计区间与采样周期。
4. **复杂度**：$O(N) \to O(1)$ 需定义 $N$ 的口径（包数或字节数）与适用路径范围，避免被读作整条处理链的复杂度结论。
5. **环境**：CPU 型号与主频、网卡型号、NUMA 与核绑定策略、DPDK 与内核版本均未列出，影响结果可复现性。

## 五、结论

在 100Gbps 口、单核条件下，改造后吞吐为 14.88 Mpps，单包端到端时延由 850 ns 降至 120 ns，内存拷贝复杂度由 $O(N)$ 降为 $O(1)$。现有数据支撑“零拷贝路径可在单核收包下达到 14.88 Mpps，并把单包时延压到 120 ns”的判断。吞吐一项缺改造前基线，暂不构成前后对比结论；跨平台结论需在补齐第四节口径后给出。
