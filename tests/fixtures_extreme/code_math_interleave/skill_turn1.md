# DPDK 零拷贝网络改造实测通报

## 一、实测结论

100 Gbps 以太网口压测条件下，改造后的单核心收包吞吐为 14.88 Mpps，单包端到端处理时延从 850 ns 降至 120 ns。单包处理的时间复杂度由 $O(N)$ 降为 $O(1)$，内存拷贝开销减少 64 GB 带宽占用。

## 二、改造内容

三项机制共同作用于收包路径：

**大页内存。** 收发包内存池与描述符环由 2MB HugePages 承载，页表遍历次数下降，地址转换开销在报文速率升高后不再构成瓶颈。

**用户态 PMD 轮询驱动。** 收包不经过中断与内核协议栈，报文经网卡 DMA 落入用户态 mbuf 后由应用直接读取，中断上下文切换与软中断开销随之消除。

**零拷贝。** 内核缓冲区到用户态缓冲区的一次复制被取消，报文数据全程停留在原地，原先用于复制的内存带宽被释放。

## 三、关键数据

| 指标 | 改造前 | 改造后 |
| --- | --- | --- |
| 单核心吞吐 | — | 14.88 Mpps |
| 单包端到端处理时延 | 850 ns | 120 ns |
| 单包处理时间复杂度 | $O(N)$ | $O(1)$ |
| 内存拷贝带宽开销 | 基准 | 减少 64 GB |

吞吐一项改造前未取得可比基线，故不列。时延与复杂度为同口径前后对比。

## 四、收包路径

收包以突发为单位轮询，单次最多取 32 个报文：

```c
// DPDK burst polling loop
uint16_t nb_rx = rte_eth_rx_burst(port_id, 0, pkts_burst, 32);
```

一次 `rte_eth_rx_burst` 调用返回 `nb_rx` 个已就绪报文，应用随即批量处理。轮询与批处理叠加，避免了逐包中断与逐包复制的双重开销。

## 五、机理

时延从 850 ns 降到 120 ns，来自三个方向的叠加：中断路径移除后，报文到达与处理之间不再有调度延迟；零拷贝消除了数据搬运；大页降低了地址转换的固定成本。

复杂度从 $O(N)$ 到 $O(1)$，对应处理路径上不再存在随规模线性增长的遍历——单包处理的工作量不再随队列长度或报文数量变化。

## 六、边界与待补数据

以下口径需在提交架构委员会前补齐，否则结论的可复现性不足：

1. **64 GB 的口径。** 原文记为“节约 64GB 带宽”，未说明是瞬时带宽（GB/s）还是压测区间内的累计搬运量，两者含义不同，需明确单位与统计区间。
2. **$O(N)$ 中 N 的定义。** 需指明 N 指突发队列长度、活跃流数量还是其他维度，否则复杂度结论无法对齐。
3. **测试条件。** 缺包长、CPU 型号与主频、NUMA 绑定方式、网卡型号、队列数、压测工具与时长。上述任一项变动都会影响 14.88 Mpps 与 120 ns 的复现。
4. **吞吐基线。** 改造前的单核心吞吐应有可比数值，否则 14.88 Mpps 缺少参照。
