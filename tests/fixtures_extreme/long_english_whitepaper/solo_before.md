**The KV Cache Is the Workload: A Technical Position on Long-Context LLM Inference**

Long-context inference has become a memory-systems problem. Model FLOPs continue to scale with denser accelerators and better kernels, while high-bandwidth memory capacity and bandwidth scale more slowly. The decode phase moves weights and KV cache for every generated token at low arithmetic intensity. Long contexts multiply the KV footprint by sequence length; batched serving multiplies it again. A serving stack that optimizes only compute will stall on HBM reads and cache capacity. This paper argues for a memory-centric design: the KV cache is a first-class workload, compression is an accuracy-budgeted trade, and speculative decoding is a conditional latency tool.

**Memory bandwidth vs compute scaling.** Decode is bandwidth-bound because each token requires reading model weights and the full KV cache; prefill is compute-bound but attention work grows quadratically with context. Compute scaling improves prefill and verification throughput, not the bytes needed for decode. Roofline analysis makes the gap explicit: decode arithmetic intensity is often below one FLOP per byte, far from the compute roof. KV cache size per token is 2 × layers × hidden dimension × bytes, and every active request adds its own cache. At long context and high batch, KV reads dominate token latency and capacity limits concurrency. The practical objective is bytes moved per accepted token, not peak FLOPs. Kernels, paging, and scheduling must reduce that metric without degrading output quality.

**KV cache compression trade-offs.** Compression spans quantization, low-rank projection, token eviction, merging, paging, and offload. Each method reduces one resource while adding another cost. Quantization lowers bytes but can damage long-tail retrieval and numerical stability; aggressive 2-bit or 4-bit caches need per-channel scaling and outlier handling. Eviction protects attention sinks and recent tokens, yet it can discard evidence needed for multi-hop questions. Low-rank compression saves capacity but may miss rare facts. Offload moves pressure to interconnect and increases tail latency. A uniform compression ratio is the wrong default. Better designs allocate per-layer and per-head budgets, protect retrieval-critical tokens, and calibrate quality against long-context tasks such as needle-in-a-haystack, multi-document QA, code completion, and summarization. The right compression policy is request-aware and reversible: cached representations should be decompressed or re-fetched when a task’s evidence demands it. Compression also adds metadata and decode-time computation; if those costs exceed saved bandwidth, the method loses. Report p50/p95/p99 latency, throughput, and task accuracy together.

**Speculative decoding trade-offs.** Speculative decoding uses a draft model to propose tokens and the target model to verify them in parallel. The method converts serial decode latency into extra compute and extra memory traffic. It pays when decode is memory-bound, acceptance is high, and batch size is low. Long-context serving weakens those conditions. Draft and target caches both consume HBM, verification reads multiple token candidates, and high batch pushes the target into compute-bound territory. Batching changes the calculus: larger batches amortize weight reads but magnify KV traffic and verification work. Acceptance rates fall under domain shift, long contexts, and sampling. A globally enabled speculator can reduce throughput and capacity. The sound approach is adaptive speculation: choose draft length and draft model from measured acceptance, batch size, context length, and SLO; share or compress draft caches; disable speculation when verification overhead dominates. Speculative decoding is a latency knob, not a universal accelerator.

**Position and recommendations.** Serving systems should treat KV cache as a memory hierarchy: hot tokens in HBM, compressed warm cache, and offloaded cold cache, with admission control based on token budgets. Compression should carry explicit quality SLOs and per-request budgets rather than a fixed ratio. Speculative decoding should be scheduled per request and per batch under measured acceptance. Hardware and software co-design should favor bandwidth-efficient cache formats, attention kernels that read less, and schedulers that reason about bytes. Benchmarks must use realistic context lengths, batch sizes, and tail latency; average perplexity hides the failures that matter. The research agenda should prioritize cache-aware serving APIs, quality-calibrated compression, and adaptive decode controllers. The memory wall will not be solved by one trick. It will be overcome by adaptive, memory-aware co-design that treats KV traffic as the central cost of long-context inference.
