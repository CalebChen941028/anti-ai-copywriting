# 用户态网络旁路技术方案选型与架构论证报告

**一、背景与结论**  
在单机40Gbps压测下，传统内核协议栈受软中断与上下文切换制约，P99时延850μs。DPDK采用HugePages 2MB、用户态PMD无锁环形队列后，单核P99降至120ns、吞吐14.88Mpps；eBPF XDP在免驱动改造下实现9.20Mpps、P99 420ns。建议核心交换层采用“**DPDK主路径、XDP辅助与降级**”的异构旁路架构，不将XDP作为超低时延主交易承载。

**二、技术权衡**  
1. **内核穿透**：DPDK完全旁路内核，轮询PMD消除中断与上下文切换，路径最短；XDP在驱动层早期钩子处理，仍受内核框架约束，但可经AF_XDP零拷贝上送用户态。  
2. **驱动维护成本**：DPDK需PMD绑定、大页、绑核、NUMA及网卡固件/驱动矩阵适配，升级维护成本高；XDP复用内核驱动，部署轻、改造小，但受内核版本与驱动支持约束。  
3. **内存拷贝开销**：DPDK由DMA直达用户态大页，零拷贝且无skb分配；XDP native/AF_XDP可零拷贝，generic模式存在拷贝和性能衰减。  
4. **安全性**：DPDK绕过内核安全策略，须独立权限、内存隔离、故障域、审计与热升级机制；XDP受验证器沙箱和最小权限约束，治理较成熟，但程序仍须签名、审计与灰度。

**三、架构决议与路线图**  
决议：核心撮合、行情、风控前置等P99敏感链路采用DPDK；入口清洗、流量镜像、监控探针、灰度降级采用XDP。设定双路径SLO：DPDK P99≤200ns、14Mpps以上；XDP P99≤500ns、9Mpps以上。  
路线图：0—3月完成基准复测与POC，验证NUMA绑核、HugePages、多队列RSS、无锁环、故障隔离和热升级；4—9月核心链路双机双活灰度，XDP承接入口安全与镜像，配置自动回退；10—12月全量推广，固化驱动/固件基线、性能与安全审计、容量模型及运维手册。风险控制上，DPDK须故障域隔离并可回退内核/XDP路径，XDP程序须签名审计，任何路径不得绕过交易风控与审计。请委员会批准按此选型进入实施。
